## 总体方案

WebGAL 将启用新的 UI 自定义方案。该方案将计划支持更加丰富的自定义选项，并支持一定程度上的布局自定义。具体来说，我们将大幅修改 WebGAL 引擎 UI 的实现方式，将布局切换到基于绝对定位的方案，以方便 UI 布局的自定义。

在本文中，“界面”指标题、文本框、存读档这样的顶层独立画面，“部件”指界面内部的具体元素（对应旧方案中的一个样式类）。

## 模板调试协议

新的模板编辑器，需要复用并扩展现有的编辑器预览协议与引擎互联。在模板调试模式下，应当有一个开关，要么预览，使得引擎可交互，要么进入编辑状态，可以直接在画布选中并编辑部件。引擎负责上报部件的位置与尺寸，编辑框留在编辑器外层实现；同时为存读档、鉴赏、历史记录等界面自动注入一套预览假数据，方便直接看到效果。

## 预制界面与自定义界面

在列表等场景下，引入界面化替换设计，弄一些预制界面，并允许导入自定义界面。比如存档整体界面，可以直接切换要网格还是列表，左侧要不要显示大型存档预览，并支持对里面的部件进一步细调。具体的会在后面的“预制界面”说明。

## UI 描述文件

新的 UI 描述文件将布局描述和样式描述放在一起。

每一个界面拥有一个 UI 描述文件，包含多个部件的描述。对于任何部件，描述都分为两部分：布局和样式。

- 布局：部件的相对位置、宽高、内外边距等
- 样式：背景图像、颜色、阴影等

由于 CSS 支持较为丰富的样式自定义选项，因此样式方面，还是继续沿用目前的 CSS in JS 方案，但是实现方式有很大差别。新方案让每个独立界面的 `.js` 自带完整的默认样式表，编辑器在它的完整副本上做字段级增改（写入 `.scss`），加载自定义样式后直接接管部件渲染，不再依赖额外的“兜底”样式。

## 布局编辑器

部件分为布局编辑和样式编辑两部分，类似 Figma。

布局编辑器主要编辑部件的变换、尺寸和边距。

当选中某个部件并打开布局编辑器时，可在预览界面中联动调整。

在界面方面，允许调整的不只是定位，要像 PPT 一样，可以选中某个部件，并使用右边的面板调整。

## 样式编辑器

样式编辑仍然使用 CSS in JS 的方案，但是相比于之前只是简单将 CSS 属性映射到可视化编辑条目的方案，本次使用更加简单和易于理解的方式实现。编辑时顶部提供一排状态锁定切换（默认 / 悬停 / 按下 / 禁用），切到“悬停”编辑时预览画布就会自动锁定在该部件的悬停态上。

### 简易模式

我们将支持简易模式。简易模式包括一些常用的配置项，比如字体描边颜色，字体颜色，阴影设定等。

简易模式也包括一个可输入一些关键定位字段的部分。这里和布局编辑器联动。

**需要特别注意的是**，简易模式最大的意义在于便捷调整一些需要联动的 CSS 属性，比如对于字体颜色，如果要设置渐变色这样的复杂样式，需要先将字体颜色设为透明，然后设置 `background-clip`，然后设置 `background`。先前的方案对用户来说不容易令人理解的就是这之间的相关性，所以可能出现调了颜色却发现没生效，或者设置了颜色后就难以调整为渐变色的情况。简易模式不走 CSS 属性可视化编辑，而是用自动化组合映射为 CSS 属性，并写到部件的样式描述区域，然后直接覆盖写入受影响的几个字段。比如对于调整字体颜色（或背景），在简易模式调整后，就同时覆盖写入 `color`, `background`, `background-clip` 三个字段。

简易模式的“简易”，是“使用简易”的简易，不一定意味着“功能简易”。如果我们可以找到好方法可视化一些复杂 CSS 属性的编辑，那么将尽可能支持它们。上面的渐变字色与阴影只是举例，后续还会尽可能支持九宫格切图底框（`border-image`）、多态图片按钮、渐隐遮罩（`mask-image`）、毛玻璃（`backdrop-filter`）等常用效果。

### 完全 CSS 自定义模式
除了简易模式外，如果需要更加细化和高级的 CSS 属性自定义，我们也支持完全 CSS 定制模式。切换到完全 CSS 定制模式后，将展示一个 CSS 代码编辑器，以供编辑。

### 简易模式与完全 CSS 自定义模式的兼容性
总的来说，支持简易模式和完全 CSS 定制模式。简易模式会覆盖相关 CSS 样式，但是也可以详细编辑。当然，简易模式只会动相关样式，如果用户通过 CSS 自定义了一些额外的属性，我们不会去碰。正如之前说的，**只覆盖写入相关字段**。

## 只支持样式编辑的部件，预制界面

对于标题、文本框等，在一个界面上只会出现一次的部件，使用绝对定位是可行的。但是对于设置页面的设置项、存读档页面的档位这样的，涉及列表渲染、交互逻辑的，则难以支持基于绝对定位的布局。WebGAL 引擎的 UI 需要改造，需要对大多数非列表部件，用绝对定位。包括列表部件的容器。但是列表项部件因为涉及多语言问题，则不能这样做。

这些部件，暂时被设定为“只支持样式编辑的部件”。然而，只允许自定义样式，不允许自定义布局会使得游戏千篇一律，因此，我们将内置多套预制界面以供直接切换（这也取代了早期设想的预设样式方案）。

比如，对于存/读档，可以是预置以下一些界面：

- 竖向列表展示
- 竖向列表展示，一行 2/3 个档位
- 左侧展示存档详情，右侧展示档位
- ...

设置、鉴赏选项也会提供类似的预制界面可选。
