正如在 RFC4 提到的，我们将采用更加灵活的新 UI 自定义方案。对于这样的方案，需要对 WebGAL 的整个 UI 架构彻底地革新。接下来介绍新 UI 自定义的技术方案。

## 独立组件化 UI

在先前的版本中，UI 和许多引擎的交互逻辑是耦合的，一些逻辑直接写在 UI 组件中，这对于后续的自定义乃至动态导入组件，都造成了很大的障碍。新的独立组件化 UI 将只处理 UI 展示，并全面采用 CSS in JS 方案以更加灵活地控制样式。所有的数据和回调，都通过参数的方式传入，这样用于展示的 UI 就和逻辑无关。

除了用于“兜底”的默认 UI 外，新的版本将支持通过动态加载 JS 的方式，来加载自定义组件，然后将默认 UI 取而代之。自定义 UI 期望为一个单 js 文件，使用库打包工具将相关样式也打入一个 js 文件。自定义 UI 采用和模板相同的分发机制，放在 template 目录下（一般来说放在顶层，并注册在 template.json 中），并可以引用 template 目录下的资源文件，和目前 template 引用图像等资源文件的方式类似，只不过是相对于模板，自定义组件更为灵活和自由。

## 模板与调试

由于自定义组件功能提供了更大的灵活度，现在在 Terre 项目内通过配置表写死的组件类将难以支撑这样的需求。更何况对于存读档、设置等界面，我们提供的多种预制组件，在布局方面都可能有很大变化，更不是原先的写死的类列表可以支撑的。

新的用于模板编辑器进一步细化编辑的类表，直接通过模板调试协议，由自定义组件提供，并发送给 WebGAL Terre。当用户开始对某个组件进行更加细节的，基于模板系统的调整时，就采用组件提供的可自定义类。

## 布局编辑与样式编辑

正如 RFC4 中所述，每一个界面（比如存读档界面）拥有一个 UI 描述文件，包含多个组件的描述。对于任何组件，描述都分为两部分：布局和样式。

如今，为了让组件分发简单，尽可能使用单个 .js 打包后文件，这里我们也让这个描述文件直接打包在 js 中，向引擎提供，并通过调试协议发送到编辑器。

## 界面调整

界面方面，我们需要大幅调整 UI 编辑界面。左侧基本不变，仍然是模板配置相关、组件选择器和资源管理器。只不过组件选择器可能需要做一些调整，以适应新的结构，由于具体的样式由下文中说的右侧编辑区处理，所以这里只显示“独立 UI 界面”层级的顶层，也就是类似于“标题”这样的选择器顶层。同时也需要也需要添加“更换组件”的按钮，以在我们提供的预制组件和用户导入的自定义 js 组件间切换。自定义 js 组件，需要被导入到当前模板的目录下，才能在这里被选择。

相比于原先放在下面的实际编辑区，新的编辑区被放在右侧，以实现两段式结构。当某个组件被选择后，右边分别展示：

1. 上栏：布局编辑器，用于编辑组件的相对位置、宽高、内外边距等，与左边的预览中可以拖拽的组件联动，设定后会更新多个 CSS 字段。
2. 下栏，Tab 简易模式（在下栏通过 Tab 切换）：我们精心设计好的，由多个 CSS 字段联动的简易字段，设定后会更新多个 CSS 字段。
3. 下栏，Tab 完全 CSS 定义（在下栏通过 Tab 切换）：分为图形编辑器和代码编辑器，逻辑基本上完全继承于当前的下方编辑区的实现，是最原始的编辑方式，可收起不用。

对于简易模式，不设单独字段，全部使用类似于 Terre 脚本图形编辑器中的解析-组装模式。比如，对于字体颜色，如果要设置渐变色这样的复杂样式，需要先将字体颜色设为透明，然后设置 `background-clip`，然后设置 `background`。那么解析的过程中，就会通过多个字段的组合，解析并分析出对应简易模式中的“渐变色字体”，并直接合并为一项编辑字段也就是字体颜色。而对合并字段的编辑，则是在编辑后，直接写入相关字段。在 RFC4 中，已经有相关讲解。

由于左侧现在只能选择顶层，也就是相当于一个界面级别的组件，所以在右侧的编辑区的“下栏”，在简易编辑 Tab，需要提供一个选择当前编辑子组件，也就是对应到旧方案的一个“类”的选择器。而如果选择的是完全 CSS 定义模式，则这个选择器只负责控制“图形编辑器”选中的类，进入代码编辑器时，仍然按照“一个顶层组件一个代码文件”的方式组织，沿用旧方案。

## 只支持样式编辑的组件（顶层组件），预置布局

如果是存读档、设置、鉴赏界面的布局，涉及列表渲染等，如 RFC4 所述，不能支持所有布局的编辑。因此，在自定义组件（和我们的预制组件）通过预览协议通知编辑器时，也允许告知“某个组件”是否支持布局编辑，如果不支持，可以直接隐藏布局编辑器中的一些字段（width, height, position, left, top 等设计定位、尺寸的），甚至完全禁用布局编辑区，只支持编辑样式。

由于即将开放基于 .js 的动态组件导入，后续也会提供 npm 脚手架，因此用户使用 AI 工具自定义组件应不难。这里只需要给用户提供一些直观的细调方式即可。我认为这是合理的，与其费劲研究一套布局描述 DSL，像 renpy 一样死磕，不如利用 AI 四两拨千斤。
